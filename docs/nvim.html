Neovim 設定說明

設定放在 ，由 symlink 到 ~/.config/nvim。

plugin 清單、選項、keymap 都以 為準；這份文件只記 code 看不出來的部分：整體架構、選用取捨、日常操作流程。

目錄

上手

在 repo 根目錄用 n（nvim 的 alias）打開。<leader> 是空白鍵。

查 keymap

  • 按 <leader>、g、[、] 這類前綴後停約 0.5 秒，which-key 會列出下一步可按的鍵和說明。
  • 忘了在哪個前綴底下，就用關鍵字搜尋全部 keymap：
:FzfLua keymaps

LSP 相關的 keymap 只在有 language server 的檔案裡出現。

跟一般 Vim 不一樣的地方

  • jk 離開 insert mode，在 <C-\> 開的底部 terminal 裡也一樣。
  • s／S 是 Flash 跳轉，加減引號、括號改用 gs 開頭的 surround。f／t 維持原本行為。
  • yank 和貼上直接用系統剪貼簿。
  • 最近開過的檔案和跳轉紀錄依 repo 分開，在哪個 repo 開就只看到那個 repo 的。
  • 不產生 swap file；undo 紀錄關掉 nvim 後仍然保留。<C-z> 不會把 nvim 丟到背景。
  • 存檔時自動 format：有 Biome 設定的專案用 Biome，其他專案一律用 oxfmt，專案沒有 .oxfmtrc.json 時套用 ~/.oxfmtrc.json。oxlint fix 只在專案有它的設定檔時跑。
  • LSP rename、在檔案樹搬移檔案時，import 會跟著更新，被改到的檔案自動存檔。
  • :e 開一個資料夾還不存在的新檔，存檔時會自動建立資料夾。
  • 其他工具（例如 AI agent）改了檔案，畫面沒更新時按 <leader>fR 重新讀取。

架構

兩個檔案

  • ：唯一的設定檔。由上而下是 選項與全域 keymap → vim.pack.add() → 各功能區塊 → LSP、lint、format、補全。 每個區塊以 -- 名稱 註解開頭，plugin 的 setup() 和它的 keymap 寫在同一段。
  • ：vim.pack 的 lockfile， 記錄每個 plugin 鎖定的 commit。內容只透過 vim.pack 的指令變動，跟 init.lua 一起 commit。

需要 Neovim 0.12 以上（vim.pack 與 :restart 都是 0.12 內建）。 所有 plugin 在啟動時就載入：vim.pack.add() 之後直接 require(...).setup()，沒有 lazy loading。

工具從哪裡來

nvim 用到的東西分散在四個來源，缺了什麼時先看它屬於哪一個：

vim.pack

lockfile 鎖版本

  • 所有 plugin
  • 各 language server 的預設設定（來自 nvim-lspconfig 的 lsp/*.lua）

Mason

ensure_installed 清單

  • 通用 language server，裝好後由 mason-lspconfig 自動 enable

Homebrew

  • neovim
  • tree-sitter-cli：編譯 treesitter parser
  • fd、ripgrep、fzf：fzf-lua
  • lazygit
  • typescript：TS 7 原生 LSP（tsc --lsp）
  • biome、oxfmt、cspell

專案 node_modules

專案有裝就優先用

  • tsc（7 以上才用專案的）
  • biome、oxfmt
  • oxlint：只來自專案

選用取捨

Plugin 管理：vim.pack

  • Neovim 內建，init.lua 不需要 bootstrap 程式碼。
  • lockfile 進 git，每台機器裝到同一組 commit；更新出問題就用 git 回退（見回退更新）。
  • 代價是沒有 lazy loading 和管理介面，安裝以外的操作都透過 :lua vim.pack.*（見日常操作）。

設定原則

  • 選項只寫跟 Neovim 預設不同的。
  • LSP keymap 沿用 0.11 起內建的 gr* 系列與 K，只補內建沒有的；其中 grr 改成 Trouble 依檔案分組的樹狀清單。
  • 操作手感向 VS Code 看齊：Tab／Enter 接受補全、自動補括號與 HTML tag、存檔時 format、references 依檔案分組。
  • keymap 清單不另外寫文件，按鍵說明都在 which-key 裡，查法見查 keymap。

分工

關注點 負責 要知道的事
語言功能 內建 LSP + nvim-lspconfig server 預設設定來自 nvim-lspconfig，init.lua 只寫覆寫的部分
補全 blink.cmp 來源只有 LSP 與 friendly-snippets
Format conform.nvim 存檔時依序跑 CLI：biome check → oxlint fix → oxfmt。 Biome、oxlint 只在專案有它的設定檔時執行；oxfmt 是預設 formatter，專案用 Biome 時才略過， 設定取離檔案最近的 .oxfmtrc.json，找不到專案的就用 ~/.oxfmtrc.json。 LSP formatting 不使用，tsc、jsonls 不會動到檔案
Lint LSP（biome、oxlint）＋ nvim-lint（cspell） cspell 沒有 LSP，由 nvim-lint 在讀檔、存檔、離開 insert 時執行，結果一樣顯示成 diagnostics
語法 nvim-treesitter（main branch） parsers 清單同時決定要裝的 parser，以及哪些 filetype 開啟 treesitter highlight／indent／fold
搜尋與選單 fzf-lua 也接管 vim.ui.select，code action 選單用的就是它
Git gitsigns、diffview、lazygit lazygit 跑在 nvim 內的 terminal tab，搭配 lazygit 的 nvim-remote preset，從 lazygit 開檔會回到同一個 nvim
終端與測試 toggleterm、vim-test <C-\> 開關底部 terminal；測試輸出固定在 9 號，用 9<C-\> 叫出來，不會跟 dev server 的 terminal 混在一起

日常操作

改完 init.lua 用 :restart 重開套用。動到 plugin 的操作，最後都把 init.lua 和 lockfile 一起 commit。

新增 plugin

  1. 在 vim.pack.add({ ... }) 加上 repo URL。要跟著 release tag 更新，寫成： 
    { src = "https://github.com/owner/repo", version = vim.version.range("1.*") }
  2. 在對應的功能區塊加 require("xxx").setup(...) 和它的 keymap。
  3. :restart：啟動時自動 clone，並寫進 lockfile。
  4. commit init.lua 與 lockfile。

更新 plugin

  1. 開啟更新確認畫面（新 tab，列出每個 plugin 待套用的 commit）： 
    :lua vim.pack.update()
    只更新特定 plugin 就傳名稱：:lua vim.pack.update({ "fzf-lua" })。 畫面裡 ]]／[[ 跳到下一個／上一個 plugin，K 看該行細節。
  2. :write 套用，:quit 放棄。
  3. :restart。nvim-treesitter 有更新時會自動跑 :TSUpdate 重編 parser（PackChanged hook）。
  4. commit lockfile。
移除 plugin
  1. 從 vim.pack.add() 和它的 setup 區塊刪掉。
  2. :restart，再從磁碟刪除（名稱是 lockfile 裡的 key）： 
    :lua vim.pack.del({ "plugin-name" })
  3. commit init.lua 與 lockfile。
回退更新
  1. 把 lockfile 還原到更新前： 
    git checkout HEAD -- ide/nvim/nvim-pack-lock.json
  2. :restart，再讓磁碟上的 plugin 對齊 lockfile，確認畫面裡 :write： 
    :lua vim.pack.update(nil, { offline = true, target = "lockfile" })
新機器與跨機器同步

新機器：照 README 跑完 brew bundle 與 node scripts/link-configs.js，第一次開 nvim 就會依 lockfile 裝好全部 plugin；Mason server 與 treesitter parser 在背景安裝，裝完再 :restart 一次。

pull 到別台機器改過的 lockfile：

  1. :restart：lockfile 裡新增的 plugin 會自動裝好。
  2. 把既有 plugin 對齊 lockfile 的版本，確認畫面裡 :write： 
    :lua vim.pack.update(nil, { target = "lockfile" })
  3. lockfile 已經沒有、磁碟上還在的 plugin，用 vim.pack.del() 刪掉（git diff lockfile 可以看出是哪些）。

新增 LSP server

server 名稱用 nvim-lspconfig 的 config 名稱，完整清單在 :help lspconfig-all。依安裝來源擇一：

  • Mason 有提供：加進 mason-lspconfig 的 ensure_installed，裝好後自動 enable。
  • CLI 走 Homebrew 或專案 node_modules：CLI 自己裝，init.lua 加一行 vim.lsp.enable("name")。

要調整 server 設定時，在 enable 之前加 vim.lsp.config("name", { ... })，內容會 merge 到 nvim-lspconfig 的預設上。開一個對應的檔案，按 <leader>cl 確認 server 有 attach。

新增 treesitter 語言

把語言加進 init.lua 的 parsers 清單，:restart 後會在背景用 tree-sitter-cli 編譯安裝。不在清單裡的語言不會開 treesitter highlight。

新增 formatter 或 linter

  • Formatter：加在 init.lua 的 conform 區塊，存檔時就會跑。
  • Linter：有 LSP 的照新增 LSP server；只有 CLI 的加在 nvim-lint 區塊（cspell 那段），結果會跟 LSP 的錯誤一起顯示。

新增 keymap

  • 寫在相關 plugin 的區塊旁邊，並帶 desc，which-key 才會顯示說明。
  • 開了新的 <leader> 前綴，在 which-key 區塊補上群組名稱，選單上才不會只顯示一個 +。
  • 只跟 LSP 有關的 keymap 放在 LspAttach 那段。

排錯

症狀 先看
檔案沒有 LSP 功能 <leader>cl 列出 attach 的 server；<leader>cL 開 :checkhealth vim.lsp；:lsp restart 重啟
Mason 的 server 沒裝好 :Mason
存檔沒有 format :ConformInfo：看該 filetype 對應的 formatter，以及是否因為找不到專案設定檔而略過
沒有語法高亮 確認語言在 parsers 清單；:checkhealth nvim-treesitter
plugin 安裝或版本不對 :checkhealth vim.pack；每次更新都記在 stdpath("log") 下的 nvim-pack.log
其他錯誤訊息一閃而過 :messages
